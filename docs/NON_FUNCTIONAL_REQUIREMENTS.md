## 1. Perfiles y entorno de prueba

Definir un equipo móvil real o emulado de recursos limitados para UI y un escritorio compatible real para inferencia local. Emulación de viewport **no** verifica modelo local, GPU, memoria, descarga, rendimiento energético ni accesibilidad de lector de pantalla. Añadir al menos un lector de pantalla real y recorrido de teclado manual. La ausencia de dispositivo compatible debe registrarse como riesgo/bloqueo de prueba, no sustituirse por mocks presentados como producto funcionando.

Para IA, separar tiempo de adquisición del modelo, inicialización, generación y rendering. Registrar estado del modelo (no disponible/descargable/listo), temperatura de prueba fría/caliente y red; evitar comparar rutas con entradas o condiciones diferentes. Medir consumo de memoria cuando las herramientas lo permitan y señalar las limitaciones de atribución; no inventar datos de batería.

## 2. Tratamiento de incumplimientos

Bloqueadores: exposición de datos privados, requisitos/fechas críticos inventados, evidencia de backend falsa, incumplimiento de ONLY_ON_DEVICE, flujo principal inaccesible, guardado con pérdida silenciosa. Reducir alcance Should antes de relajar estos controles. Metas de rendimiento que no se alcancen requieren registrar medición, causa, impacto y decisión explícita, nunca afirmar «optimizado» sin cifras.
